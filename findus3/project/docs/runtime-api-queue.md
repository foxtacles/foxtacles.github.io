# Portable VM API coverage and remaining queue

The executable inventory is [runtime-api.json](../artifacts/analysis/runtime-api.json), generated by [inventory_runtime_api.py](../scripts/inventory_runtime_api.py) from every canonical `.lasm` file. It records 56 opcode kinds, 262 external-call names, and 20 named global properties. Every used opcode kind has a route in the current Rust dispatcher. Dispatch presence establishes neither correct operands nor faithful behavior; runtime scenarios remain necessary.

## Implemented startup/calendar fixes

- `pathName` returns the launch directory retained by the player, while `moviePath` follows the currently loaded movie. `searchPaths` is a persistent, mutable Lingo list. Full player reset releases its reference before resetting the allocator.
- Movie requests inspect the basename for an extension, preserve URL query/fragment suffixes, normalize Windows separators, and try current-directory and configured-search-directory candidates. Extensionless names try the current format followed by Director `.dir`/`.dxr`/`.dcr` alternatives. Network task reuse compares resolved locations; identical relative names from different movie directories no longer alias. The web package's file manifest handles case and published-extension aliases on static hosts.
- `systemDate.month/day/year` use local, one-based calendar fields on native and WebAssembly builds. The host can set external parameter `findusDate=YYYY-MM-DD` to select a reference date without modifying original bytecode. Absent/empty uses the real local clock; invalid explicit dates raise a clear error. The web “all days” option uses December 24. This override applies to `systemDate`; formatted date strings remain local wall-clock displays.
- Short/abbreviated/long date and time properties now have implementations, using the runtime's existing English formatting policy. Full localization is still unimplemented. Tick/timer semantics remain distinct from the calendar override.
- `mouseCast` returns the packed member number under the current pointer. This is essential for the calendar's chest view: the third cast's member 60 is `((3−1)<<16)|60 = 131132`, matching the original `spel−131131` calculation. The hit-test semantics follow the existing stage picker.
- `quit()` stops the portable session and sound; the surrounding web UI remains available to restart. Browser-tab closure is outside the projector implementation.
- Named and legacy numeric `soundLevel`/`soundEnabled` getters, plus setters, now route to the audio owner's master gain state. Calendar levels 7, 4, and 1 no longer disappear into no-op system-property assignments.

Validation: six native path/API tests pass, including master sound property round trips, plus two native date tests covering nine date boundaries and invalid dates. [findus_calendar_probe.rs](../runtime/dirplayer/findus_calendar_probe.rs) executes the original compiled `KALENDER.checkDate` handler; all nine cases pass: August 31→25, September 1→1, November 30→1, December 1→1, December 16→16, December 24→24, December 25→25, January 1→25, leap-day February 29→25.

## Gameplay compatibility fixes validated from original resources

- Director ticks use exactly 60 ticks per second. Dividing milliseconds by 16 produced 62.5 ticks per second and shortened authored timers. Two native tests cover full-second and fractional boundaries.
- Macintosh-authored CASt metadata names now decode with the file platform's MacRoman encoding, matching the already decoded literal strings. DAG13's `member("grön3")` now resolves member 38; previously it missed the name and created invalid card-back references. This metadata fix does not guess the encoding of damaged/high-byte Lingo identifiers in the raw decompiled sources.
- Forward frame changes no longer dispatch frame/movie `exitFrame` twice. The dispatcher already invokes them after sprite behaviors; its caller repeated them. A native regression executes DAG13's original frame 12 initialization and counts exactly one frame 13 event. The real web test subsequently matches all eight pairs.
- `updateStage()` yields to the browser on an elapsed 8 ms budget even during mouse-up hover loops. Named mouse/time access and `rollOver()` mark polling for the VM's cooperative loop yield. This permits physical release/input delivery without recursively starting another frame.
- Queued mouse press/release dispatch waits for active Lingo scopes, and discards a stale queued press/release if authored polling has already navigated to another movie or frame. Physical button state is applied immediately when input is delivered/enqueued. A delayed queued press/release never overwrites newer physical state; this prevents a press delayed by construction dialogue from trapping its own release behind a busy loop. Input-handler busy loops still receive physical releases.
- Cast-member slots and Lctx script IDs are separate identities. `get_script_for_member` no longer falls back from an absent member to an unrelated matching Lctx ID. DAG01's dead member 22 previously resolved member 27 (the rooster narration), blocking racing. The native race regression runs original checkpoint/car/timer initialization and three real driving frames, verifies scopes unwind, and verifies the timer is updated.

The [Construction 2 interrupted-tap regression](../artifacts/runtime-tests/construction-interrupt/KONSTR02.json) verifies the delayed-input fix in the browser. The authored blocking dialogue may ignore a short buffered tap whose button has already been released; it no longer leaves the player stuck, and a subsequent fresh Return tap succeeds.

Evidence is recorded in [api-tests.json](../artifacts/runtime-tests/api-tests.json). Original-resource regressions are [findus_frame_dispatch_probe.rs](../runtime/dirplayer/findus_frame_dispatch_probe.rs) and [findus_race_dispatch_probe.rs](../runtime/dirplayer/findus_race_dispatch_probe.rs). These tests exercise actual recovered programs or isolate their event count; they do not establish complete game playability.

## Remaining static API findings

| Finding | Actual use | Next action |
| --- | --- | --- |
| `openFile`, `closeFile`, `setPosition`, `readLine`, `writeString`, `status` | `SHARED16/Lscr-31`, dormant treasure persistence helpers | These are Xtra-instance calls, and FileIO handlers exist. Do not misclassify them as missing global builtins. Validate their async dispatch and storage contract only if a reachable caller is found. |
| `HittatKartbit` | `SHARED16/Lscr-35` | No corresponding handler was recovered. Trace reachability before implementing anything; it belongs to retained treasure/map code. |
| `FixaFFindus`, `FixaPPettson` | `ROUTS/Lscr-80` | No corresponding handlers were recovered. These are retained helper dependencies, not standard Director APIs; no active game caller has been established. |
| `return` as an external-call opcode | 111 instructions | Already handled by `player_ext_call` as VM control flow. A builtin-dispatch-only inventory would incorrectly flag it. |
| `beep`, preload/unload commands | Many activities | The runtime accepts several as no-ops. Preloaded assets may make this sufficient for correctness, but memory pressure, streaming, and beep feedback differ from Director. |
| `puppetTransition`, film loops, sprite geometry/ink, audio completion | Many activities | A symbol/handler exists, but these require visual and timing validation. Other work in this project owns those subsystems. |
| Formatting/localization and high-byte identifiers | Shared helpers and selected day scripts | Preserve byte identity and document English date formatting. See [recovery quality](recovery-quality.md); a Unicode spelling guess must not change handler/variable identity. |

The inventory classifies a call as “script-defined” if a declaration exists anywhere in recovered code. It does not prove that declaration is in a loaded cast or reachable through the current event scope. Missing-library, numeric-member, parent-script, and score-attachment errors therefore remain possible even when all listed APIs have dispatch routes. Browser tests should record entry, actual interaction, and exit/restart behavior for every activity rather than use loading alone as a pass criterion.
